# 编写 AGENTS.md 最佳实践

`AGENTS.md` 是**为 AI Agent 准备的项目入职手册**，告诉 AI 在这个项目中能做什么、该怎么做、绝不能做什么。它不是 README（给人看），而是可执行的配置指令（给 AI 读）。

---

## 一、核心内容（写什么）

好的 AGENTS.md 聚焦于 AI 无法从代码中自行推断的项目特定规则。按优先级排列：

| 板块 | 必须 | 可选 |
|------|:----:|:----:|
| 构建/测试/Lint 命令 | ✅ | |
| 代码风格规范（引用 `docs/rules/` 原文，不内联） | ✅ | |
| 工作流边界（必须做 / 先问 / 绝不碰） | ✅ | |
| 入口文档（项目地图：去哪找信息） | ✅ | |
| Git 提交规范 | | ✓ |
| 领域特定知识（第三方库特殊用法等） | | ✓ |
| 自动化助手行为 | | ✓ |

**引用优于内联**：已有规范文档（如 `docs/rules/unix_pythonic_guid.md`）时，用 `@文档路径` 引用，**不复制内容**。

## 二、结构与组织（怎么写）

### 2.1 硬约束：AGENTS.md ≤ 100 行

超过 100 行的内容拆到子文档中，保持根文件精简。

### 2.2 引用策略：立即加载 vs 按需加载

| 类型 | 标记方式 | 示例 |
|------|----------|------|
| **立即加载**（Agent 启动读） | `@文件路径` 写在 AGENTS.md 正文 | `@docs/rules/unix_pythonic_guid.md` |
| **按需加载**（触碰相关代码时才读） | 子目录 `rules/` 下用 `paths:` 匹配 | `.claude/rules/pytest.md` `paths: tests/**/*.py` |

**判断标准**：全局约束（代码风格、架构原则）→ 立即加载。领域特定（某个模块的约定、某类测试的写法）→ 按需加载。

### 2.3 拆分规则

根目录 `AGENTS.md` 是总索引。详细规则拆到：
- `docs/rules/`（通用规则，跨代理）
- `SKILL.md`（复杂任务的"技能包"）

## 三、结构模板

模板与§一表格的"必须"项一一对应：

```markdown
# AI Agent 最高契约

## 构建与测试
- lint: `ruff check . && ruff format --check .`
- test: `pytest`
- run: 

## 代码风格
- @docs/rules/unix_pythonic_guid.md — 架构宪法（立即加载）
- 函数 <50 行，文件 <300 行，嵌套 <3 层

## 工作流边界
- 必须做: 代码修改后运行 lint + 测试
- 先问:  涉及范围/架构决策不确定时
- 绝不碰: `config/*.yaml`、`.env`、credentials 文件

## 入口文档
- @README.md
- @docs/specs/requirements.md — 需求文档
```

可选板块（Git 规范、领域知识等）按项目需要追在模板末尾即可。
