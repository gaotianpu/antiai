# USER — 个人习惯与偏好

> 基于交互行为推断，持续更新。

---

## 命名约定

| 偏好 | 示例 |
|:---|:---|
| 功能名带 `agent-` 前缀 | `agent-doc-gather` |
| 项目本地 skill 放 `skills/` | `skills/cloudsync/` 而非 `.agents/skills/` |
| 项目配置目录用 `.agents/` | 非 `.pi/` |
| `change_logs/` 用下划线 | `change_logs/` 而非 `changelogs/` |
| 文件名不用中文 | `deletion_lesson.md` 而非 `误删除教训.md` |
| 生成本地产物可入库 | `file_mapping.md` 正常追踪，不排除 |

## 文档习惯

- **脚本外提** — 可执行脚本独立为 `.sh` 文件，SKILL.md 只保留调用命令
- **文档规整** — 定期做全文审查，清除重复附录、修正引用、统一结构
- **跨项目追踪** — 关注约束文档在各工作区的副本分布和版本新旧
- **变更可追溯** — diff 报告写入 `change_logs/`，留存历史记录

## 工作流程

- **频繁提交** — 每完成一个逻辑变更就 `git commit`，不做大积攒
- **云备份** — 每次工作告一段落后执行云备份
- **先看方案再动手** — 喜欢先出问题清单/方案，确认后再执行
- **撤销用 git** — 回退操作走 `git checkout/reset`，不手动删除
- **做完总结** — 错误/教训整理成文档保存

## 沟通风格

- 指令简洁直接（「好」「执行」「提交git」「云备份」）
- 会及时纠正错误路径或命名
- 重视分析沉淀（USER.md、change_logs/ 教训文档）
