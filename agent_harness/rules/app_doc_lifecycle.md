# APP 文档生命周期：职责划分与模板骨架

> 定义单个 APP 在 `docs/specs/apps/` 下四类文档的职责边界和模板结构。与 `doc_rules.md`（TradeOS vs APP 横向解耦）互补，本文档聚焦纵向生命周期。

## APP 内部文档职责划分

每个 APP 在 `docs/specs/apps/` 下按四个独立文件组织，分别对应需求→设计→测试→验收的生命周期：

| 文档 | 职责 | 读者 | 产出物 |
|------|------|------|--------|
| **`{app}.requirements.md`** | **做什么** — 业务目标、场景矩阵、配置模型、MVP 分期。人工编写，AI 禁止改动 | 所有人（需求权威源） | 判定依据 |
| **`{app}.design.md`** | **怎么做** — 类结构、核心流程、组件接口、关键决策、决议记录 | 开发者（实现者） | 实现蓝图 |
| **`{app}.test-spec.md`** | **怎么测** — 测试范围界定、依赖隔离策略、用例表（P0/P1/P2）、Daemon 专项测试 | 测试编写者 | 测试用例库 |
| **`{app}.acceptance.md`** | **怎么验** — 端到端验收场景、操作步骤、预期日志、checklist、常见失败排查 | 验收者（人或 AI） | 验收检查 |

**关系链**：`.requirements.md` → `.design.md` → `.test-spec.md` → `.acceptance.md`，前者是后者的上游。四个文件保持独立，读者不同、粒度不同、视角不同，不应合并。

### 常见反例：上级文档写了下一级的内容

最典型的跨层污染是**上级文档出现下级文档才该有的细节**：

| 反例 | 出现位置 | 问题 | 应属于 |
|------|---------|------|--------|
| `PositionState`、`self._positions` 等代码级细节 | requirements.md | 需求写代码实现 | design.md |
| 23 个代码块、`if/for/await/asyncio.gather` 等 Python 关键字伪代码 | design.md | 设计写接近真实代码的伪代码 | 验收脚本（pytest） |
| `assert "BTC/USDT" in app._positions` 断言代码 | acceptance.md | 验收写测试断言 | test-spec.md |

具体表现：

**反例 1 — 需求文档出现类名和实例变量**
```
❌ 各标的 PositionState 写入 self._positions
✅ 系统记录每个标的的持仓状态（标的、方向、数量、开仓价、开仓时间）
```

**反例 2 — 设计文档出现接近真实代码的伪代码**
```python
❌ for item in items:
       qty = balance / count * ratio
       order = await exchange.place_order(...)
       if order.failed:
           retry()
✅ 进场流程：资金分配 → 并行市价单开仓 → 全部完成后统一对账
```

**反例 3 — 验收文档出现断言代码**
```python
❌ assert "BTC/USDT" in app._positions
   assert state.direction == "long"
✅ 预期日志：position opened, symbol=BTC/USDT, direction=long
```

判断依据：如果一段内容引用了**代码中的类名、变量名、方法签名**（如 `PositionState`、`self._positions`、`get_positions()`），它就不是"做什么"或"怎么验"——它是"怎么做"或"怎么测"。

## 修改记录规范

文件头部 `<!-- 修改记录 -->` 仅在有实质性内容变更（新增/移除场景、修改配置结构、重写流程）时追加。拼写修正、措辞调整等不影响语义的变更不记入——减少文件哈希变化，提高 LLM 缓存命中率。

## 设计文档中的代码/伪代码原则

设计文档中的代码相关内容按以下原则处理：

| 类型 | 示例 | 应放位置 | 理由 |
|------|------|---------|------|
| 配置结构 YAML | `take_profit: 0.05` | 设计文档内联 | contract 性质，改了就是改设计 |
| 接口签名 | `on_signal_received(raw_data)` | 设计文档内联 | 设计级契约 |
| 算法说明（语言无关） | 树形流程 `│ ├─ └─`、公式 | 设计文档内联 | 不会因语言/框架变化而过时 |
| **接近真实代码的伪代码** | `if/for/await/asyncio.gather` | **不应出现在设计文档** | 不可执行、不可验证、会过时 |

被验收测试替代：设计文档用自然语言描述流程和决策，可执行细节由验收脚本（pytest）承载。
