# 验收文档撰写 + 执行

## 工作流

```
摸清边界 → 排出阻塞顺序 → 撰写文档 → 逐项执行 → 展示结果 → 记录盲点
```

---

## 1. 摸清边界

先回答三个问题，决定**验收的范围**：

1. **目标模块是什么？**
2. **模块对外依赖有哪些？**（外部服务、配置、第三方等）
3. **哪些依赖在本轮验收范围内，哪些在范围外？**

**原则**：
- 只看模块自身的**功能闭环**——配置是否能启动、输入能否收到、数据能否正确处理
- 外部依赖用 mock/stub 替代，不在验收中测试外部系统
- **不包含**架构约定的检查（由代码审查阶段覆盖）

---

## 2. 排出阻塞顺序

按 MVP 原则，**前一项未通过不进入下一项**。从核心闭环开始，逐步细化：

```
P0 ── 模块启动 + 配置校验
  └── P0 ── 核心功能 A
       └── P0 ── 核心功能 B
            └── P1 ── 增强功能 C
                 └── P1 ── 增强功能 D
```

判断标准：
- **P0**：功能不可用就无法验收后续项
- **P1**：功能缺失不影响核心闭环验证

---

## 3. 撰写文档

每项包含四个要素：

### 3.1 验证命令

一条可复制的 CLI 命令，让用户或 Agent 可以直接运行：

```bash
# 好的例子
python run.py --mode=test --app=my_app

# 差的例子
启动 app（略）
```

**验收脚本**：编写可独立运行的验收测试脚本，用 pytest 直接运行：

```bash
python -m pytest tests/<模块>/<验收脚本>.py -v
```

### 3.2 预期产出

用具体描述，不用模糊词汇：

```markdown
**预期日志**：
MyApp started, mode=file_watch, timeout=300
```

产出类型包括：
| 类型 | 示例 |
|------|------|
| 日志 | 特定日志行 |
| 文件 | 输出文件、状态记录 |
| 终端输出 | 命令的 stdout/stderr |

### 3.3 验收标准

用 checkbox 列表，每条可独立判定通过/不通过：

```markdown
- [ ] 配置缺失 → 错误退出（不静默）
- [ ] 非法配置 → ValueError（不崩溃在其他地方）
- [ ] 正常配置 → 启动成功日志
```

每条标准对应一个具体的**行为断言**，避免笼统的"功能正常"。

### 3.4 验收场景表格

对于有多分支逻辑的功能，用表格列出：

| 场景 | 前置条件 | 预期行为 |
|------|---------|---------|
| 正常流程 | 配置完整 | 启动成功 |
| 异常 A | 配置缺字段 | 明确报错退出 |
| 异常 B | 外部超时 | WARNING 跳过 |

---

## 4. 逐项执行

### 4.1 执行策略

验收优先通过验收脚本自动化执行，人工辅助检查日志/产出。

```python
for 每一项 in 验收文档:
    运行验证命令（优先用验收脚本）
    检查预期产出
    if 通过:
        标记 ✅
    else:
        判断失败原因分类:
            - 本模块 bug → 修复
            - 测试覆盖率不足 → 补测试用例
            - 外部依赖问题 → 标记盲点
```

### 4.2 边界内 vs 边界外 —— 决策树

发现的问题超出验收范围时：

```
发现的问题是否阻塞验收项的真实生效？
  ├─ 否 → 记录盲点，继续验收
  └─ 是 → 依赖链有多深？
         ├─ 改一处即可 → 直接改（无需问人）
         ├─ 改多处、但逻辑是机械的 → 列影响范围让用户确认后改
         └─ 涉及业务判断 → 必须问人
```

**核心原则**：边界内的事做到位，边界外的事记录盲点。

---

## 5. 展示结果

### 5.1 逐项报告

```markdown
| 验收项 | 状态 | 说明 |
|--------|------|------|
| **P0-1 App 启动** | ✅ | 日志匹配 |
| **P0-2 信号接收** | ⚠️ | 功能正常，但 XXXX（见盲点） |
| **P0-3 开仓执行** | ❌ | `place_order` 未调用（超时未处理） |
```

### 5.2 盲点清单

```markdown
## 盲点清单

| # | 描述 | 依赖方 | 建议处理时机 |
|---|------|--------|------------|
| 1 | 外部检查逻辑已加，但适配器未填充数据 | 适配层 | 下次适配器专项 |
```

### 5.3 总体结论

```markdown
✅ 验收通过（P0 全部通过，盲点已记录）
⚠️ 有条件通过（P0 核心通过，但存在盲点需后续跟进）
❌ 验收未通过（P0 存在阻塞项）
```

## 6. 与验收最佳实践的关系

| 最佳实践原则 | 本 skill 对应步骤 |
|-------------|-----------------|
| 快速交付可运行 demo | §3.1 给出 CLI 命令 |
| 对问题分类 | §4.1 失败原因分类 |
| 批量处理关联问题 | §4.2 决策树 |
| 展示可验证的结果 | §5 逐项报告 |
| 主动问盲点 | §5.2 盲点清单 |

---

## 7. 参考模板

验收文档模板应包含：
- P0/P1 阻塞顺序布局
- 验收场景表格格式
- CLI 命令 + 预期日志 + checkbox 的四要素结构
- 常见失败模式排查表

验收脚本模板应包含：
- 与验收文档一一对应的逐项验收函数
- 外部依赖用 mock 替代、pytest 可跑的独立脚本

项目中的实际案例可在 `docs/` 中按命名约定查找。
