## 核心流程

### 阶段 1：加载审查依据

**必须阅读的文档**：

```bash
# 审查准则
docs/analysis/pandas-best-practices.md    # 6 条原则 + 5 项检查清单 + 严重程度分级
```

阅读时确认以下核心原则已理解到位：

| 原则 | 要点 | 检查信号 |
|------|------|---------|
| 原则 1 | 循环内不动 DataFrame | 循环内 `df['col'] = ...` |
| 原则 2 | 先取 numpy 数组，再进循环 | 循环内 `df['col'].iloc[i]` |
| 原则 3 | 中间结果用局部变量，不挂 df | `df['tmp']` 后不再引用 |
| 原则 4 | 整列操作优于逐行操作 | `for i in range(): df.loc[i]` |
| 原则 5 | 预分配优于动态扩容 | `result = []` + `append` |
| 原则 6 | 避免循环内 concat | 循环内 `pd.concat` |

> **原则 ↔ 检查项映射**：原则1对应检查项1，原则2对应检查项2，原则3对应检查项3，原则4对应检查项1/2，原则5对应检查项5，原则6对应检查项4。详细检查方法见阶段3。

### 阶段 3：逐文件对照检查清单

对每个 `.py` 文件，按以下 5 项逐条排查：

#### 检查项 1：高频循环中是否存在 DataFrame 写入？

**识别信号**：
- `for` / `while` 循环体内出现 `df['xxx'] = ...`
- 循环次数 > 100 且每次写列

**判定方法**：
```
# 基于阶段2的粗扫结果定位循环行号，以下用于逐文件确认：
grep -n "for.*range" <file>       # 该文件所有循环
grep -n "df\[" <file>             # 该文件所有 df 列写入
# 人工确认循环体和 df 写入是否重叠
```

#### 检查项 2：循环中是否使用了 .iloc / .loc / .iat / .at？

**识别信号**：
- 循环中使用 `df['col'].iloc[i]`、`df['col'].loc[i]`、`df.iloc[i]['col']`
- 同一循环对同一列多次索引

**优化方向**：循环前用 `col = df['col'].values` 取 numpy 数组

#### 检查项 3：是否存在本应是局部变量的 DataFrame 列？

**识别信号**：
- `df['xxxx'] = ...` 赋值后，该列在 return 语句中未出现
- 该列在后几行被覆盖或不再引用

**优化方向**：将 Series 赋值改为局部变量，不写入 df

#### 检查项 4：是否存在循环内 concat / merge / join？

**识别信号**：
- 循环内出现 `pd.concat`、`df.merge`、`df.join`
- 传入的 df 越来越大

**优化方向**：用 list 收集分片，循环结束后一次性 concat

#### 检查项 5：是否使用了 Python list + append 处理大数据量？

**识别信号**：
- `result = []` + `result.append(...)` 的循环
- `len(df)` > 10000

**优化方向**：改用 `np.zeros(n)` 预分配 + 下标赋值

### 阶段 4：定级

按以下标准对每个问题定级：

| 级别 | 条件 | 示例 |
|------|------|------|
| **严重** | 循环次数 × 写入列数 > 100,000 | `for i in range(7200): df[f'col_{i}'] = ...` |
| **中等** | 循环次数 > 1000 且每次有 iloc 调用 | `for i in range(5000): df.iloc[i]` |
| **轻微** | 循环次数 < 100 或数据量 < 1000 行 | `for i in range(10): result.append(x)` |

**额外严重情况**：
- 虽不写 df 列，但循环内每次做全列 rolling 操作，循环次数 > 1000（如 `pos()` 的 7000+ 次 rolling）
- 总时间复杂度 O(N × loop_count) 且 loop_count > 1000，即使不违反 pandas 反模式也定 **严重**

---

### 阶段 5：数值一致性分析（严重问题的额外步骤）

当发现严重性能问题且涉及**算法级优化**（非纯实现级优化）时，需补充数值一致性分析：

1. **分析算法数学结构**：确认各次迭代之间是否有计算可共享
2. **明确约束**：区分"数值绝对不变" vs "数值近似可接受"
3. **列出优化手段的数值影响表**：

| 优化手段 | 数值变化 | 加速潜力 | 适用场景 |
|----------|---------|---------|---------|
| 纯实现级优化（numpy 预分配等） | **不变** | 低（< 2x） | 小修小补 |
| 公式代数恒等变形 | **不变** | 极低 | 代码可读性 |
| 跳步采样 / 截断 | **改变** | 高（10x+） | 需验证秩相关 > 0.95 |
| 近似算法替换 | **改变** | 高 | 需端到端验证 |

4. **结论输出**：给出明确的"可行/不可行"判断，附验证方案

### 阶段 7：迭代深化（用户追问时）

- **追加不新建**：后续深入讨论直接追加到已保存的报告文档
- **用户纠偏优先**：用户对定级/影响有不同判断时，先接受再找依据印证
- **追问即素材**：用户追问的细节本身就是文档素材，回填到报告中
- **拿不准的标记待定**：不替用户做业务决策（策略参数、阈值等）
- **涉及代码修复时**：修正方向须用户确认后执行，不自作主张

## 禁止事项

- 不替用户做业务决策（"这个策略应该去掉"、"这个参数应该改小"）
- 不擅自修改策略代码 — 先出报告，等用户确认后再改
- 不把不同模块的分析混入同一份报告
- 不对性能无问题的代码做无意义"优化"（如把 `df['col']` 改成局部变量但没有循环问题）
- 定级时严格遵守分级标准，不夸大不缩小
